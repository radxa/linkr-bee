### 本次包含

- **每块板有可识别的 BLE 名称。** 默认名为 `Linkr Bee XXXX`，`XXXX` 取硬件 MAC 最后四个十六进制字符（例如 `58:BF:25:33:07:8C` → `078C`），不依赖会变化的 BLE 身份地址。`@n?` 查询、`@n=<名称>` 设置、`@n default` 恢复默认；`@linkr name...` 保留兼容写法。名称支持 1–29 个 UTF-8 字节，可直接使用中文和 emoji（受字节数限制，例如 7 个四字节 emoji 正好 28 字节），并持久化到 settings。
- **旧固件仍然可以搜索和配对。** 新固件仍以 Management Service UUID 发现，并在连接后校验 Device ID；名称只是显示用途。没有 Management Service 的早期 NUS-only 固件保留 `Linkr BLE UART...` 固定名称作为兼容信号，TUI 和 Web 仍会列出并允许连接，终端可用，配件设置按能力自动禁用。新式 `Linkr Bee XXXX` 名称本身不能替代 Management Service 校验。
- **TUI 不再按新名称前缀猜测设备。** 扫描接受 Management Service 设备，以及使用旧 `Linkr BLE UART` 名称的 NUS-only 设备；新名称没有服务时不会被当作 Linkr Bee。同名设备用地址尾号区分，不会把另一台 Linkr Bee 或同名设备当成目标。
- **按需 UART 波特率检测。** WROOM 固件可用 `@a` 启动一次有界检测，`@a?` 查询状态，`@a stop` 取消；板上 `linkr-autobaud` GPIO 键也可启动。检测只在请求时运行，不会在启动时自动改串口。发布用的 WROOM 默认构建保持 `CONFIG_LINKR_BLE_BRIDGE_UART_AUTOBAUD=n`；本地台架验证通过 out-of-tree 配置启用。C3/C5 的配对与 autobaud 行为保持不变。
- **Web 控制面板按钮居中。** `#panelToggle` 与主题、语言按钮使用同一套 30×30 图标按钮盒，图标在边框内水平/垂直居中；桌面顶栏不再因字体度量差异换行。
- **Web 跨浏览器适配与 BLE 改名。** Web 连接 BLE 后可读取、设置和恢复 BLE 名称，语言切换和断线状态会同步更新控件。设备选择同时匹配 `Linkr Bee`、旧 `Linkr BLE UART` 名称和 Management Service；旧 NUS-only 固件自动降级为仅终端会话。桌面顶栏固定单行并对长设备名做省略；统一文本缩放、Firefox/Chromium 滚动条槽位；不支持 `backdrop-filter` 的引擎使用实色玻璃回退，避免 Linux Firefox 与 Windows Edge 打开时出现不同的高度和对比度。

### 刷写与校验

固件包包含镜像、配置、ELF/MAP、板型元数据、镜像校验和及刷写脚本。解压对应板型的 ZIP，在目录中执行：

```sh
python3 -m pip install esptool
sh flash_firmware.sh --port /dev/cu.usbmodemXXXX
```

请按本机实际串口修改 `--port`。脚本按镜像名选择芯片与写入地址并保留设置分区；详细步骤见 [开发指南]({{REPO}}/blob/{{TAG}}/docs/DEVELOPMENT.zh-CN.md)。

下载本发布页的 `SHA256SUMS` 与所需附件，用 `sha256sum`（Linux）或 `shasum -a 256`（macOS）计算文件摘要，与清单中同名条目逐项比较。`release-manifest.json` 记录附件大小、SHA-256、组件版本、提交和构建来源。桌面文件名保留 `{{TUI_VERSION}}`，内容从同一提交重新构建。

### 平台说明与验证范围

- C3/C5 默认要求首次配对时 GPIO1 接地，配对完成后释放，已绑定主机可直接重连。WROOM-32 受板型条件限制默认关闭物理配对授权检查，附近主机均可申请配对；加密与绑定要求仍保留。见 [配对说明]({{REPO}}/blob/{{TAG}}/docs/BLE_PAIRING.md) 和 [WROOM 硬件差异]({{REPO}}/blob/{{TAG}}/docs/HARDWARE.md)。
- WebDAV 当前仅支持匿名 HTTP；WROOM-32 因 DRAM 限制禁用 WebDAV。
- Web Bluetooth 需要兼容的 Chrome/Chromium/Edge 与 HTTPS 或 localhost；Linux Firefox 不支持 Web Bluetooth，但可用同一页面的局域网 WebSocket 桥接。AI 服务需用户自行配置模型端点和凭据。
- macOS 包未做开发者签名与公证。本次不提供 iOS IPA 或 HarmonyOS HAP；HarmonyOS 共享 Web 资源构建通过，但发布环境未重新完成 HAP 编译和真机 BLE 验证。
- 本次通过 Rust 默认、CLI-only、TUI-only 测试与 lint，Python 主机测试，Web/mobile 单元与浏览器回归，5 个固件板型、Android APK 和 10 个桌面目标构建。WROOM 实机已验证默认名称 `Linkr Bee 078C`、`@n?` / `@n=<中文名>` / `@n default` 与断电持久化；C3/C5 镜像已构建，但本轮未重新烧录做真机回归。旧 `Linkr BLE UART-3` 发现、NUS-only 终端回退和 emoji 字节校验由主机测试覆盖。构建与模拟测试不代表所有板型/移动设备已完成真机验收。

Project release **{{TAG}}** of Linkr Bee, a BLE/LAN UART bridge with Web, mobile and desktop clients and a configurable Pi serial assistant. Every attachment is rebuilt from commit `{{SHA}}`.

Highlights: per-board BLE names (`Linkr Bee XXXX` from the hardware MAC, with persisted `@n` overrides including Chinese and emoji within the 29-byte limit), legacy NUS-only firmware discovery and terminal fallback in the Web/TUI clients, Management-Service/Device-ID verification for current firmware, Web BLE-name controls, on-demand UART autobaud for WROOM builds, a centered Web panel toggle, and Firefox/Edge layout parity. Every component in this release is version `{{FIRMWARE_VERSION}}`.

Choose the firmware ZIP for your exact board, `bee` for the interactive terminal, or `bee-cli` for scripts and agent sessions. Verify downloads against this release's `SHA256SUMS`; `release-manifest.json` provides provenance. The Android APK is debug-signed. macOS packages are not Developer ID signed or notarized. C3/C5 require GPIO1 low for new pairing. WROOM-32 permits pairing without a physical authorization gate and has WebDAV disabled. WebDAV on supported boards accepts anonymous HTTP only. Web Bluetooth needs a Chromium-based browser; Firefox can use the LAN WebSocket bridge, but its page cannot open Web Bluetooth. CI and packaged-binary smoke checks passed; WROOM naming was verified on hardware, while C3/C5 were rebuilt but not reflashed in this pass. Legacy `Linkr BLE UART-3` discovery, NUS-only terminal fallback and emoji byte validation are covered by host tests.
