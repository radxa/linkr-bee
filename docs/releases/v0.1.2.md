Linkr Bee 项目级发布 **{{TAG}}**：把 BLE 改名能力补齐到每一个主机客户端的一次更新。所有附件都由同一提交 `{{SHA}}` 构建。

`{{TAG}}` 是项目发布标签；本次所有组件统一为 `{{FIRMWARE_VERSION}}`：固件、Rust CLI/TUI、Web/mobile 包，以及 Android 调试 APK 的原生 `versionName`。

### 本次包含

- **每个主机客户端都能改名。** 固件的 `@n?` / `@n=<名称>` / `@n default` 在 v0.1.1 已经可用，本次把它补进所有主机入口：
  - 桌面 TUI 的网络视图新增 BLE 名称区：显示当前名称，以及 *修改名称*、*恢复默认*、*读取名称* 三个动作；输入按固件同样的规则校验（1–29 个 UTF-8 字节，无控制字符），中文和 emoji 可用，写入前有确认卡片，写入后由板子回读确认。
  - `bee` / `bee-cli` 新增 `--query-ble-name`、`--rename-ble NAME`、`--reset-ble-name`，并有对应子命令 `query ble-name`、`set ble-name <名称|default>`；`bee --serve` 新增 `ble-name` 操作，可带 `name` 或 `default`。
  - Python 参考客户端新增同名三个参数，发送前在主机本地校验名称。
  - C 参考客户端（Linux/BlueZ）新增同名三个参数，并实现了一条最小的 Management Service v1 通道：连接后读取 Protocol Info 和 Device ID，订阅 Response indication，再发送管理帧。终端部分仍是 legacy NUS；只有 NUS 的旧固件会被明确拒绝，而不是静默失败。
- **名字是标签，地址是身份。** 名字随时可以改，所以客户端不再用名字认板子：默认按 Management Service 找板子，改名后靠地址连接；连上后主机主动向板子问一次名字（`@n?`），界面显示的就是板子自己的回答，改完名立刻刷新；给了名字却没匹配上时，会列出听到的板子并提示用 `--address`。**固件侧同时修了一个 bug**：扫描响应在开始广播时就被拷进控制器，所以改名后旧名字会一直广播到链路断开——现在装上新名字会立刻重新广播一次，空中的名字和管理通道报的名字一致。
- **名称规则没有变化。** 仍然是 1–29 个 UTF-8 字节，中文和 emoji 可用，默认名由硬件 MAC 最后四位生成（`Linkr Bee XXXX`），改名写入 settings 后重启保留，恢复默认会删除自定义名。
- **发现规则没有变化。** 固件仍以 Management Service UUID 发现并校验 Device ID；广播名只是显示用途。旧固件的 `Linkr BLE UART...` 固定名称仍可搜索和配对，且不会被改名。

### 刷写与校验

固件包包含镜像、配置、ELF/MAP、板型元数据、镜像校验和及刷写脚本。解压对应板型的 ZIP，在目录中执行：

```sh
python3 -m pip install esptool
sh flash_firmware.sh --port /dev/cu.usbmodemXXXX
```

请按本机实际串口修改 `--port`。脚本按镜像名选择芯片与写入地址并保留设置分区；详细步骤见 [开发指南]({{REPO}}/blob/{{TAG}}/docs/DEVELOPMENT.zh-CN.md)。

下载本发布页的 `SHA256SUMS` 与所需附件，用 `sha256sum`（Linux）或 `shasum -a 256`（macOS）计算文件摘要，与清单中同名条目逐项比较。`release-manifest.json` 记录附件大小、SHA-256、组件版本、提交和构建来源。桌面文件名保留 `{{TUI_VERSION}}`，内容从同一提交重新构建。

### English

Project release **{{TAG}}** of Linkr Bee, a BLE/LAN UART bridge with Web, mobile and desktop clients and a configurable Pi serial assistant. Every attachment is rebuilt from commit `{{SHA}}`.

Highlights: the advertised BLE name can now be read, set, and restored from every host client, and every host treats it as a label rather than an identity. A board is found by the Management Service it advertises and reached by its address; the name shown is the board's own answer to `@n?`, read as soon as a link comes up and again after every rename; a name that matches nothing lists the boards that were heard and says how to reach one by address. The firmware also broadcasts a renamed board at once - the scan response is copied into the controller when advertising starts, so the old name used to stay on the air until the link dropped. The desktop terminal's network view carries the current name with *Rename*, *Restore default* and *Read name*; `bee` and `bee-cli` add `--query-ble-name`, `--rename-ble NAME`, and `--reset-ble-name`, with the matching `query ble-name` and `set ble-name <name|default>` subcommands and a `ble-name` operation for `bee --serve`; the Python reference client adds the same three options; and the Linux/BlueZ C client grows a minimal Management Service v1 path that reads Protocol Info and the Device ID before it sends a frame. Names are 1–29 UTF-8 bytes, Chinese and emoji are allowed, the default is still `Linkr Bee XXXX` from the hardware MAC, and a change is persisted in the board's settings. Every component in this release is version `{{FIRMWARE_VERSION}}`.

Choose the firmware ZIP for your exact board, `bee` for the interactive terminal, or `bee-cli` for scripts and agent sessions. Verify downloads against this release's `SHA256SUMS`; `release-manifest.json` provides provenance. The Android APK is debug-signed. macOS packages are not Developer ID signed or notarized. No iOS IPA or HarmonyOS HAP is included.

C3/C5 require GPIO1 low for new pairing. WROOM-32 permits pairing without a physical authorization gate and has WebDAV disabled. WebDAV on supported boards accepts anonymous HTTP only. WROOM autobaud is opt-in in the released configuration; C3/C5 pairing and autobaud behavior is unchanged. Web Bluetooth needs a Chromium-based browser; Firefox can use the LAN WebSocket bridge, but its page cannot open Web Bluetooth. CI and packaged-binary smoke checks passed; the naming commands were verified on WROOM hardware in the previous release, and the host entries added here are covered by host tests. The C client's Management path was not re-run on hardware in this pass.
