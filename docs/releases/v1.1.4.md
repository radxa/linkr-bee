Linkr Bee 项目级发布 **{{TAG}}**：把版本线统一到一个数字，把 Harness 插件变成"智能体可以直接操作的串口终端"，并修掉代码审查报告里两条会卡住发版的硬阻塞与一批安全、正确性问题。所有附件都由同一提交 `{{SHA}}` 构建。

`{{TAG}}` 是项目发布标签；本次所有组件统一为 `{{FIRMWARE_VERSION}}`：固件（Kconfig 默认值）、Rust CLI/TUI、npm 上的 `linkr-bee-cli`、Web/手机包、Android 调试 APK 的 `versionName`、Python 参考客户端，以及 DeepSeek Harness 插件 `dsh-linkr-bee`。`python3 tools/check_versions.py {{TAG}}` 是这条承诺的可执行版本，CI 会在编译前先跑一次。

### 本次包含

- **一条版本线。** 此前 CLI/插件已经走到 1.1.2，而固件、Web、手机端仍停在 0.1.2（本次一并统一到 1.1.4），项目级发布会在三处直接失败。现在全部统一为 `{{FIRMWARE_VERSION}}`，并新增 `docs/releases/{{TAG}}.md`（就是本文件）与 CI 的版本一致性门禁：标签、Kconfig、`web/about-data.js`、`mobile/package.json`、`tools/linkr_ble_terminal.py`、`Cargo.toml`、两个 npm 包互相不一致时构建不会开始。
- **裸 CLI 二进制进入发布白名单。** `linkr-bee-cli` npm 包在首次使用时会下载 `bee-cli-<target>` 并用 `SHA256SUMS` 校验后执行；这些文件现在会被 `tools/assemble_release.py` 当作独立的 `cli` 类资产收进发布（此前会被判为"unexpected desktop artifact"而让发布失败），并且不参与版本一致性推断——它们的文件名本来就不带版本。
- **插件：智能体可以直接操作右侧串口终端。** `dsh-linkr-bee@{{FIRMWARE_VERSION}}` 新增 `linkr_bee_console` 工具（`open`/`focus`/`clear`/`type`/`key`/`read`/`state`/`resize`），配合 Host 侧的控制通道 `GET /linkr-bee/panel/stream`、`POST /linkr-bee/panel`、`POST /linkr-bee/exec` 与 64 KiB 控制台环形缓冲 `GET /linkr-bee/console/read`：智能体可以把面板打开、在同一个 shell 里打字、按命名键、读回板子说过的话，并把命令输出留在人正在看的那块终端里。面板本身也补齐了体验：头部显示链路与实时 tty 尺寸、断线一行横幅加重连按钮、空状态、重挂载/刷新后恢复画面。
- **一步安装。** 插件把 `linkr-bee-cli` 声明为依赖，`dsh plugin add dsh-linkr-bee` 会一并带上命令行客户端；解析顺序是 `cliPath` → `$LINKR_BEE_CLI` → 随插件安装的启动器 → `PATH`。客户端包自 1.1.3 起不包含任何安装脚本（pnpm 的构建脚本白名单不会再拦安装），首次调用时才下载并校验平台二进制。TUI（完整的 `bee` 终端程序）仍是独立下载。
- **审查报告修复。** 依据 `build-demo/review/REVIEW.md`：MCP「仅高危/完全授权」模式下分片输入可绕过审批（H3）已改为"审批不豁免破坏性命令、跨调用拼接后再分类、无法静态解析的输入一律送审"；Rust BLE 在通知字节层去重会吞掉合法续片（H4）改为按消息层去重；板子回 `ERR ... unsupported` 时能力未被隐藏、导致不支持的模块留在屏幕上（M7，违反 `AGENTS.md` 的能力驱动规则）改为在错误分支里也置能力为 false；报告/审计脱敏漏掉 JSON 引号形式与 `curl -u`（M8）；鸿蒙签名材料从版本库移出（M14）；键栏 30px 触控目标恢复到 36px（M18）；Web 侧未定义的 bit 6 分支删除（M1）；`DESIGN.md` 与实际生效的 skin-v2 色阶、三套阴影词汇对齐（M2/M3）；连接模型、队列行为、DEVELOPMENT 构建路径的中英文文档与实现对齐（M11）；鸿蒙订阅按特征属性区分 notify/indicate（M13）、断线清空通知队列（M15）、桥接超时文档（M17）；LAN 无 token 的风险警告写得更醒目（L1）；`probe_tools` 只在观测到 `LINKR_TOOL:...:available` 后才解锁工具（M16）。

### 已知限制

- 固件侧的 UART 改参/发送竞态（M4）、WiFi 扫描代际（M5）、Reliable UART 丢块的可观测性（M6）、未认证 WebSocket 槽位配额（M9）属于需要 Zephyr 工具链与真机复现的改动，本次未改代码，保留待硬件验证；`H4` 的修复与单元测试已在 Rust 侧完成，真机行为仍建议复核。
- 本地 `tools/linkr-tui/target`（约 13 GB）与 `build-*` 目录未清理，均被 `.gitignore` 覆盖，不影响仓库。

### 构建与验证

所有组件由同一提交 `{{SHA}}` 构建，构建记录见 [CI]({{REPO}}/actions/runs/{{RUN_ID}})；本地按 [开发指南]({{REPO}}/blob/{{TAG}}/docs/DEVELOPMENT.zh-CN.md) 可复现：`python3 -m unittest discover -s tests`、`cd mobile && npm test`、`cargo test --locked`（两种 feature 组合）、`python3 tools/check_versions.py {{TAG}}`、`cargo build --release --no-default-features --features cli`。

### 下载选择

- 桌面终端：`linkr-bee-{{FIRMWARE_VERSION}}-<target>.tar.gz` / `.dmg`，命令行面是 `linkr-bee-cli-{{FIRMWARE_VERSION}}-<target>`；只想在 Harness 里用，装 `linkr-bee-cli` npm 包即可。
- 固件：按板型选择 `linkr-bee-<board>-firmware-<chip>.zip`，`@i?` 回报的版本应与本页一致。
- Web：`linkr-bee-{{TAG}}-web.zip`；手机端：`linkr-bee-{{TAG}}-android-debug.apk`。
