# Linkr TUI 使用教程

适用版本：**bee 0.1.2**（项目发布 tag `v0.1.2`，从发布 tag 对应的提交构建；CI 全平台构建，见 Releases 页 `v0.1.2`）

本目录这批二进制由 tag `v0.1.2` 的 GitHub Actions 构建，文件名使用 0.1.2 正式写法。
本构建包含颜色与符号自适应、启动闪屏、命令面板、F1 帮助换行（英文按词断行）、
「关于」卡片，以及新的开源组件页（`L` 或 `bee --licenses`）；完整第三方许可证文本见
每个归档内的 `THIRD_PARTY_LICENSES.md`。

本目录内容：

| 文件 | 说明 |
|---|---|
| `linux/` | Linux 安装包与压缩包（`.deb`：amd64 / arm64 / armhf / i386；`.tar.gz`：x86_64 / aarch64 / i686 / armv7） |
| `windows/` | Windows 压缩包（`.zip`：x86_64 msvc / gnu、ARM64、i686，解压即用） |
| `macos/` | macOS 磁盘映像与压缩包（`.dmg` 与 `.tar.gz`，Apple Silicon / Intel） |
| `cli/` | CLI 精简构建（同一程序、关掉界面特性，程序名 `bee-cli`）+ 命令行说明（给脚本与 Agent 用） |
| `SHA256SUMS` | 本目录 28 个桌面产物的校验和 |
| `使用教程.md` | 本文件 |

Linkr TUI 是一个跑在电脑终端里的程序，用来连接 **Linkr Bee 桥**：看串口输出、查板子状态、给板子配网、管理日志上传，还带一个查看 AI 助手会话与任务的面板。

---

## 一、快速开始

### Linux（.deb 安装包）

按机器架构选择：`amd64`（常见 PC）、`arm64`（ARM 服务器/新树莓派）、`armhf`（32 位 ARM 开发板）、`i386`（32 位 x86 老机器）。

```sh
sudo apt install ./linux/linkr-bee_0.1.2_arm64.deb    # 换成你机器对应的文件名
bee --version                                   # 应输出 bee 0.1.2
bee                                             # 启动界面
```

不用包管理器也行：`sudo dpkg -i linux/linkr-bee_0.1.2_arm64.deb`，若有依赖提示再 `sudo apt-get -f install`。
安装包依赖系统自带的 `libdbus-1-3`（桌面发行版基本都已装好），并要求 glibc ≥ 2.39（对应 Ubuntu 24.04、Debian 13 及以后；更老的系统 apt 会直接提示依赖不满足）。

非 Debian 系发行版（Fedora、Arch 等）用压缩包，glibc 要求同上：

```sh
tar xzf linux/linkr-bee-0.1.2-x86_64-unknown-linux-gnu.tar.gz   # arm64 / i686 / armv7 换成对应那份
./linkr-bee-0.1.2-x86_64-unknown-linux-gnu/bee --version
```

### Windows

解压对应系统的包（`.zip`，右键「全部解压缩」或用 7-Zip），进入解压出的目录：

| 系统 | 文件 |
|---|---|
| 64 位 Windows（推荐） | `windows/linkr-bee-0.1.2-x86_64-pc-windows-msvc.zip` |
| 64 位 Windows（备选） | `windows/linkr-bee-0.1.2-x86_64-pc-windows-gnu.zip`（功能相同；哪份跑不起来就换另一份） |
| Windows on ARM（骁龙本） | `windows/linkr-bee-0.1.2-aarch64-pc-windows-msvc.zip` |
| 32 位 Windows | `windows/linkr-bee-0.1.2-i686-pc-windows-gnu.zip` |

```powershell
.\bee.exe                # 启动界面
.\bee.exe --scan         # 列出附近的 Linkr Bee 板子
```

在旧版控制台（Windows Terminal 之外的 `conhost` 窗口）里运行时程序会自动做兼容处理：
去掉合成粗体、把宽度会变两格的符号换成等宽 ASCII、右侧留出滚动条的宽度，避免文字错位或被裁掉。
用 Windows Terminal 时不做任何改动（界面按设计稿显示）。

### macOS

`.dmg` 双击打开，把里面的 `bee` 拖到任意目录（比如 `~/bin`）；也可以解压 `.tar.gz`，两者内容相同。
按芯片选一份（M 系列用 `aarch64`，Intel 用 `x86_64`）：

```sh
hdiutil attach macos/linkr-bee-0.1.2-aarch64-apple-darwin.dmg   # 或 tar xzf ...tar.gz
./linkr-bee-0.1.2-aarch64-apple-darwin/bee
```

首次运行若被 Gatekeeper 拦下，在「访达」里右击 → 打开，允许一次就行；从网络下载的映像若被隔离，
可执行 `xattr -d com.apple.quarantine <文件>` 后重试。`macos/README.md` 里还有在这台 Mac 上源码构建的方法。

### 启动之后

- 之前连过的板子：自动按记住的蓝牙地址重连；
- 第一次：自动扫描附近的 Linkr Bee 板子——只发现一台就直接连上，发现多台会列出清单（↑↓ 选择，Enter 连接）。

> 需要系统蓝牙已开启（Linux 下 BlueZ 正常运行时一般无需额外配置）。

两条与「切换设备」有关的说明：

- 扫描**只听这一次**：列表里只会出现这次扫描听到的板子，之前见过但已断电的不会再出现；名字统一用板子的蓝牙地址（老版本记下的 `HCI0/DEV_…` 路径会在第一次用到时自动换成地址）。
- 连上之后顶栏会显示这次连接的信号强度（`-41 dBm` 这类读数，按强弱配色）；没连上时不显示。

## 二、界面结构

```
┌ 顶栏：● 状态 · BLE/LAN 传输 · 地址 · RX/TX 速度图 ────────────────┐
│ 侧栏                 │ 主区（F2 终端 / F3 诊断 / F4 网络 / F5 助手）│
│  连接                │                                              │
│  视图                │                                              │
│  快捷发送            │                                              │
│  监控                │                                              │
├ 底栏：Ctrl+P 面板 · F1 帮助 · F2-F5 视图 · Ctrl+Q 退出 ───────────┤
└ 右下角：通知（toast），结果与问题都从这里说一声 ──────────────────┘
```

- 顶栏状态圆点：**○** 未连接 · **◐** 连接中 · **●** 已连接 · **◆** 失败；右侧是收（绿）/发（蓝）速度图。
- 侧栏（`Ctrl+↑` 聚焦，`Esc` 返回主区）：连接区（状态、传输方式、连接/断开、切换设备）、视图区、快捷发送（Enter 发送，`reboot` 之类会先确认）、监控区。
- 右下角通知会自动消失；`Ctrl+P` 面板里可以翻看历史通知。

## 四、四个视图

### F2 终端
键进去什么就发给板子什么；板子的回显与输出都画在这里。往上翻历史会暂停「自动跟随最新」，回到最底或**一打字**就恢复跟随。`Ctrl+L` 清屏。

**编码只有 UTF-8 一种**（板子上的 Zephyr 控制台与我们这座桥都发 UTF-8）。读不出来的字节会画成 `�`（每个坏字节一个，后面的正常内容不受影响），同时：

- 底栏状态右边会多出 `乱码 nB`（n 是坏字节累计数）；
- 第一次出现时会弹一次黄色通知，说明这两类原因，之后不再重复弹；`Ctrl+L` 清屏后重新计数、也会重新提醒一次。

看到乱码时按顺序查两件事：

1. **串口参数对不对**（最常见）：`bee --query-uart` 读板子当前的 `uart=波特率,数据位,校验,停止位,流控`；不对就用 `bee --uart 921600,8,n,1,none` 这种形式改回来。板子侧默认见固件 Kconfig（115200 8N1）。
2. **板子是不是根本没发 UTF-8**：有些系统/程序按 GBK 等编码打印。可以按通知里的提示核对；把板子设为 UTF-8 输出即可。

窗口较窄时底栏可能放不下 `乱码 nB`（底栏宁可整块省掉也不画半截），这时以那条通知为准 —— 同一条消息也会收进「通知记录」（`Ctrl+P` 打开命令面板，搜「通知记录」）。

旧版 Windows 控制台（conhost）里 `�` 会显示成 `?` —— 这是为了不让控制台把 `�` 画成两格宽、把整行挤歪；含义与计数完全一样。

相关命令行选项：

- `--local-echo` 本机回显；
- `--line-mode` 整行按下 Enter 才发送；
- `--enter cr|lf|crlf|raw` 把 Enter 翻译成指定字节再发。

### F3 诊断
按 **`r`** 向桥发 `@i?`，把返回的 `@info` 行画成与 web 端一致的表格（固件、系统、UART、WiFi、上传……）。8 秒内没有回音就报超时（与 web 行为一致）。`PgUp`/`PgDn` 翻页；新的一次读取会回到顶部。

> 管理读取是 BLE 专属：LAN 连接下该视图会说明为什么读不了。

### F4 网络（配网与上传）
- **WiFi 状态行**：Enter 查询（`@w?`）；「扫描」列出板子能看到的网络（`@w scan`）；「连接」输入 SSID 与密码并下发（`@w=…`）；「断开」忘记网络（`@w off`）。
- **配网是事件驱动的**：从排队 → 连接中 → DHCP → 已连接（带 IP）/ 失败（带错误码），全过程由桥主动上报的事件自动刷新，不需要手动重查；若 45 秒内没有最终结果，会自动补一次 `@w?` 兜底。
- **WebDAV 行**：查看/设置日志上传地址（`@d?` / `@d=`）、关闭上传（`@d off`）。
  > WebDAV 属于设备协议；ESP32-WROOM 构建因 DRAM 关闭了该功能，此时查询或设置会显示板子自己的 `ERR unknown command`，主机不会把这一行藏掉。
- **BLE 名称行**：显示板子自己的名字——连上之后程序会主动向板子问一次（`@n?`），显示的就是板子的回答；默认是 `Linkr Bee XXXX`（`XXXX` 取硬件 MAC 后四位），改过名就是新名字。三个动作：*修改名称*（`@n=<名称>`）、*恢复默认*（`@n default`）、*读取名称*（`@n?`）。
  > 名称为 1–29 个 UTF-8 字节，中文和 emoji 都可以用；输入框会先按固件同样的规则校验，固件会拒绝的名字在发出去之前就被挡下。改名会写进板子的 settings，重启后仍然保留；恢复默认会删掉自定义名，重新回到由硬件 MAC 生成的 `Linkr Bee XXXX`。
  > **名字是标签，地址是身份**：板子靠广播的 Management Service 被找到、靠蓝牙地址被连上；改名后程序会立刻重新读取并刷新这一行，别的客户端改的名也会在下次连上时显示出来。设备行显示的名字同样来自板子的回答，不再是扫描时听到的旧标签。
  > 改名是 BLE 专属功能：LAN 连接下这一段会说明为什么改不了。

### F5 助手
查看这台设备的 AI 助手会话、任务列表与设备笔记，并配置模型端点：

- `Ctrl+Shift+K` 聚焦输入框，输入任务后 Enter 提交（未配置端点时会提示先去配置）；
- `Ctrl+Shift+S` 打开设置窗口：端点、模型、API Key、附加请求头、**接口协议**、**推理强度**、
  **上下文窗口**、**最大输出**，再加笔记一行。协议与推理强度用 `←` / `→`（或空格）切换，两个
  数字字段只收数字；
- 三种接口协议都支持：`OpenAI 兼容接口`（`/chat/completions`，OpenAI、DeepSeek、Ollama、vLLM…）、
  `Anthropic Messages 接口`（`/v1/messages`，地址填 `https://api.anthropic.com/v1` 这类版本化基址）、
  `Google Gemini 接口`（`generateContent`，地址填 `https://generativelanguage.googleapis.com/v1beta`）。
  协议必须与地址匹配，否则请求会被服务商拒绝；
- 推理强度 `关闭` / `低` / `中` / `高`：不同协议按各自的方式表达（OpenAI 兼容接口发
  `reasoning_effort`，Anthropic 与 Gemini 换算成思考预算 token），`关闭` 时请求里不带任何相关字段。
  模型的思考内容不会显示、也不会存进会话；
- 上下文窗口与最大输出留空即用内置默认值（32768 / 4096）。窗口填得太小、连系统提示词都装不下时，
  设置窗口里会直接给出警告；
- `Ctrl+Shift+M` 切换模式；`Ctrl+Shift+N` 清空会话；
- 终端视图（`F2`）右侧还贴着一栏同内容的助手面板：`F6` 收起 / 展开；窗口太窄时面板不占位，
  想展开会被提示——按 `Ctrl+B` 收侧栏，或 `F5` 看整屏。

### 关于 `@` 管理命令
`F1` 帮助里的「命令速查」列着常用命令（`@i?` `@u?` `@w?` `@d?` `@s?` 及扫描、开关等），Enter 即发。板子的任何答复里若带 token，**上屏前一律打码**（`token=***`），通知与日志同样处理。

## 五、命令行用法（不打开界面也能干活）

> 界面与命令行是**同一份实现**：界面版不带界面参数时它就是命令行工具。只要命令行的人可以直接取
> `cli/` 里的 CLI 精简构建（同一程序、关掉界面特性，程序名 `bee-cli`，裸跑会说明本构建没有界面），
> 说明见 `cli/README.md`。
>
> 下文示例里的 `bee` 指已安装的程序（Windows 下写作 `bee.exe`）。

**一次性查询**（连接 → 问 → 打印 → 退出）：

```sh
bee --scan                        # 列出附近的 Linkr Bee 板子
bee --query-info                  # @i?
bee --query-uart                  # @u?
bee --query-wifi                  # @w?
bee --query-webdav                # @d?
bee --json --quiet --query-wifi   # 脚本用：JSON Lines，适合管道
```

**BLE 名称**（读、改、恢复默认；名称 1–29 个 UTF-8 字节，中文和 emoji 可用）：

```sh
bee --query-ble-name              # @n?，读当前广播名
bee --rename-ble "测试😀"          # @n=测试😀，改名并持久化
bee --reset-ble-name              # @n default，恢复 MAC 默认名
```

**配网与上传**：

```sh
bee --wifi "MySSID,MyPassword"    # 连接 WiFi（SSID,密码）
bee --wifi "MySSID" --wifi-key-file pw.txt   # 密码改为从文件第一行读
bee --wifi-scan                   # 扫描网络
bee --wifi-off                    # 忘记网络
bee --webdav http://host:port/u   # 设置上传地址
bee --webdav-off                  # 关闭上传
```

**连接方式**：

```sh
bee --ble-address EE:C7:42:34:48:CF   # 指定蓝牙地址
bee --ble-name "Linkr Bee"            # 按显示名找（名字可改；多台时用 --ble-address）
bee --lan-host 192.168.0.102          # 走局域网 WebSocket（也可给完整 ws:// URL）
bee --lan-token <TOKEN>               # 该桥要求的 token；也支持 --lan-token-file 或 $LINKR_LAN_TOKEN
bee --transport ble|lan|stdio         # 锁定传输方式（锁定后界面里不可切换）
```

**其它**：

```sh
bee --cli-then-tui --query-wifi   # 先跑一次查询，再留在界面里
bee --no-terminal --query-info    # 只跑命令，不进界面
bee --print-frame 100x30          # 渲染一帧文本（没有真终端时预览界面）
bee --lang zh|en                  # 界面语言
bee --theme dark|light|nord|gruvbox|dracula|solarized
bee --view terminal|diagnostics|network|assistant   # 打开即停在这个视图
bee --overlay help|palette|notices|confirm|wifi|webdav|settings   # 预览某个窗口
bee --uart baud,data,parity,stop,flow   # 设置 UART 参数
bee --loopback-test               # 回环自测
bee --bridge -                    # 回环桥：离线试用界面
```

**常驻会话（给脚本与 AI Agent 用）**：

```sh
bee --ble-name Linkr --serve      # 保持一条连接，从 stdin 逐行读 JSON 请求
```

一次性的命令行每问一句都要重新拨号（蓝牙要好几秒），`--serve` 只拨一次、一直用：

```console
$ bee --ble-name Linkr --serve
{"event":"ready","program":"bee","version":"0.1.2","link":"ble:name:Linkr","ops":[…]}
{"id":1,"op":"exec","cmd":"uname -a"}
{"event":"begin","id":1,"op":"exec"}
…（与 `--json` 命令行相同的事件）…
{"event":"end","id":1,"code":0}
```

- 每个请求由 `begin`（带 `id`、`op`）与 `end`（带 `code`）框起来，`code` 就是一次性命令行会返回的退出码；
- 链路是**懒拨号**：`state`、`quit` 与格式错误的请求行都不需要板子，第一个需要板子的请求才连接；
  拨号失败回 `{"event":"error","code":"not_connected"}`（码 255）且**会话继续**，等板子就绪再发一次即可；
- 请求行不是合法 JSON、或操作名不认识，回 `{"event":"error","code":"bad_request"}`（码 2），会话同样继续；
- stdin 关闭即退出（码 0）；请求里加 `"format":"text"` 可让请求内部的事件按文本输出（`begin`/`end` 两行仍是 JSON）；
- 各操作的字段写法（`exec` / `uart` / `wifi` / `loopback-test` …）与 `ops` 列表见 `cli/README.md`。

## 六、记录与排查

- `--log-file 文件`：把板子发出的每个字节追加写盘（会话留档）。
- `--debug-io`：跟踪**两个方向**的字节。
  - stderr 被重定向到文件/管道时，直接写 stderr；
  - 在终端里运行时写 `$TMPDIR/linkr-trace-<进程号>.log`（权限 0600），启动时弹通知告知路径；
  - 命令面板里也可以随时开关。
- 常见现象：
  - `le-connection-abort-by-local`：断开连接时 BlueZ 的常见日志，**正常现象**，不是故障。
  - 扫不到板子：板子不总是广播；连过一次的设备按地址直连更稳（程序会替你做）。
  - 查询/诊断超时：管理命令的窗口是 8 秒；板子忙时再按一次 `r` 即可。
  - 终端里满屏 `�`、底部写 `乱码 nB`：本程序**只按 UTF-8 解码**，这表示板子发来的字节不是合法 UTF-8 文本。先 `bee --query-uart` 核对串口参数（波特率/校验/停止位），必要时 `bee --uart 921600,8,n,1,none` 改正；若参数无误，则板子端在输出非 UTF-8 编码（如 GBK），请改为 UTF-8。详见「F2 终端」。
  - token 只以打码形式出现；记得的 token 存在 `~/.config/linkr/lan-tokens`（0600），不会进日志与通知。

## 七、拿到后自测清单

先校验完整（Linux/macOS：在 `tui-release/` 下运行 `sha256sum -c SHA256SUMS`；Windows：`certutil -hashfile <文件> SHA256` 对照 `SHA256SUMS`）。

> 发布页附带的 `SHA256SUMS` 使用扁平文件名；本目录这份按子目录路径排列，两者对应同一批文件。

然后：

```sh
bee --version                    # 应输出 bee 0.1.2
bee --print-frame 100x30         # 无终端也能看一帧（主界面）
bee --print-frame 100x24 --overlay splash        # 启动闪屏（带 logo）
bee --print-frame 100x24 --overlay palette --lang zh   # 命令面板：一级动作 + 分类窗口
bee --print-frame 205x46 --overlay help --lang zh      # 宽屏：对话框不压住右侧助手面板
bee --print-frame 100x30 --overlay help --lang zh      # 帮助按框宽换行：键列留白、说明完整不被裁
bee --print-frame 100x40 --overlay about --lang zh     # 关于：图标/名称/字段居中，贡献者与项目地址完整
bee --bridge -                   # 回环桥：离线浏览界面
bee --scan                       # 能看到 Linkr 板子
bee --query-info --transport ble --ble-address XX:XX:XX:XX:XX:XX
bee --query-uart                 # 核对串口参数：uart=115200,8,N,1,none
bee --query-ble-name             # 读广播名：ble-name: name=Linkr Bee 078C,custom=no
bee                              # 界面里试：F3 按 r 出表格 / F4 查询 WiFi / Ctrl+T 换主题 / F1 帮助
                                   # Ctrl+P 搜「关于」：透明 logo（无底板）、居中的字段与贡献者地址
echo '{"id":1,"op":"state"}' | bee --bridge - --serve   # 常驻会话：应先 ready 再出结果与 end
```

界面里若底栏出现 `乱码 nB`（或通知里提到不是有效 UTF-8），按「F2 终端」一节的两步排查：先用 `--query-uart` 核对串口参数，再确认板子输出是不是 UTF-8。
